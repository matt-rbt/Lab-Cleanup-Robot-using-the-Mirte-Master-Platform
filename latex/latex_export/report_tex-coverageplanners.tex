\subsubsection{Coverage Planners}

This section presents the algorithms employed for the discovery of portable objects. While a comprehensive technical analysis of these algorithms is beyond the scope of this work, they are described with sufficient detail to enable understanding of their application within our framework. For in-depth technical details and formal derivations, the reader is referred to the original publications cited herein.

import cv2
import numpy as np
import matplotlib.pyplot as plt
import ipywidgets as widgets

def interactive_path_slider(
    image_path,
    csv_path,
    title="Path Viewer",
    color=(0, 255, 255),
    thickness=1,
):
    """
    Visualize a path stored in CSV over an image.

    Parameters
    - - - - - - - - - -
    image_path : str
        Occupancy map image.

    csv_path : str
        CSV with columns:
            x,y
            74,19
            75,20
            ...
    """

    plt.ion()

    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
    # Load image
    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

    map_img = cv2.imread(image_path, cv2.IMREAD_GRAYSCALE)

    if map_img is None:
        raise ValueError(f"Could not load image: {image_path}")

    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
    # Load path
    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

    path_pixels = np.loadtxt(
        csv_path,
        delimiter=",",
        skiprows=1,
        dtype=np.int32,
    )

    if path_pixels.ndim == 1:
        path_pixels = path_pixels.reshape(1, 2)

    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
    # Draw path
    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

    vis = cv2.cvtColor(map_img, cv2.COLOR_GRAY2RGB)

    cv2.polylines(
        vis,
        [path_pixels],
        isClosed=False,
        color=color,
        thickness=thickness,
    )

    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
    # Create figure
    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

    fig, ax = plt.subplots(figsize=(8, 8))

    ax.imshow(vis)
    ax.set_title(title)
    ax.axis("off")

    robot_dot, = ax.plot(
        path_pixels[0, 0],
        path_pixels[0, 1],
        "o",
        color="yellow",
        markersize=10,
    )

    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
    # Slider
    # - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

    slider = widgets.IntSlider(
        value=0,
        min=0,
        max=len(path_pixels) - 1,
        step=1,
        description="Waypoint",
        continuous_update=True,
        layout=widgets.Layout(width="800px"),
    )

    def update(change):

        idx = change["new"]

        x = path_pixels[idx, 0]
        y = path_pixels[idx, 1]

        robot_dot.set_data([x], [y])

        fig.canvas.draw_idle()

    slider.observe(update, names="value")

\paragraph{Preprocessing}

Before the map can be used to plan a path, a common preprocessing algorithm can be abstracted.
Coverage path planners generally use either a binary map of the free space,
(free=1, occupied=0) or the polygons constructed from the boundaries of the free space.

The input to the algorithm can be any 2D image displaying the free and occupied pixels.
In this case the input will be the costmap directly. First the costmap is thresholded to create a Figure~\ref{fig-original_costmap}, which is the first output.

\paragraph{Morphology-Based Skeleton Path Planner}

The first implemented method, based on the work of (\citet{skeleton}), (\citet{skeleton2}), derives a coverage path from the morphological skeleton of the free space. See the algorithm below.

\textbf{Input:} Occupancy grid $\mathcal{M}$, robot start position $\mathbf{p}_0 \in ℝ^2$\newline
\textbf{Output:} Ordered waypoint segments $\mathcal{P} = [P_1, P_2, \ldots, P_k]$


\bigskip
\centerline{\rule{13cm}{0.4pt}}
\bigskip

\begin{enumerate}
\item $B \leftarrow$ threshold($\mathcal{M}$, lethal\_threshold)
\item Extract contours from $B$, group by containment into polygon groups $G_{poly}$
\item \textbf{For each} polygon group $g \in G_{poly}$:

\begin{enumerate}
\item $S \leftarrow$ medialAxis($B$) ~~~~\textit{(skimage skeletonize)}
\item $W \leftarrow$ skeletonToWorldCoords($S$)
\item $G_{graph} \leftarrow$ buildKDTreeGraph($W$, radius $= r_{path}$)
\item bridgeDisconnectedComponents($G_{graph}$)
\item $L \leftarrow$ findLeafNodes($G_{graph}$) ~~~~\textit{(nodes with degree 1)}
\item $v \leftarrow$ nearestLeaf($\mathbf{p}_0$, $L$)
\item $\mathcal{Q} \leftarrow [v]$, $\quad V_{visited} \leftarrow ∅$
\item \textbf{While} $V_{visited} \neq L$:

\begin{enumerate}
\item $V_{visited} \leftarrow V_{visited} ∪ \{v\}$
\item $r \leftarrow$ nearestLeafByGraphDistance($v$, $L ∖ V_{visited}$, $G_{graph}$)
\item $\pi \leftarrow$ shortestPath($v$, $r$, $G_{graph}$)
\item append $\pi$ to $\mathcal{Q}$
\item $v \leftarrow r$
\end{enumerate}


\item $P_i \leftarrow [W[u] \;\forall\, u \in \mathcal{Q}]$
\item append $P_i$ to $\mathcal{P}$, set $\mathbf{p}_0 \leftarrow P_i[last]$
\end{enumerate}


\item sanitiseWaypoints($\mathcal{P}$, $\mathcal{M}$)
\item \textbf{Return} $\mathcal{P}$
\end{enumerate}


\bigskip
\centerline{\rule{13cm}{0.4pt}}
\bigskip

The free space is extracted using the methods discussed in the previous section. The polygons are used and converted to a binary map as to not produce too many branches for the robot to navigate through. This map is then skeletonized to extract waypoints, see \texttt{Figure \{number\} \textless fig-skeleton\_free\textgreater }.

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.7\linewidth]{files/0497c73abdc7b1d5cf514d0510d36ca9.png}
\caption[]{Morphological skeleton extracted from the free-space representation of the environment.}
\label{fig-skeleton_free}
\end{figure}

Once the waypoints are obtained, a graph is constructed and leaf nodes are extracted. In the graph leaf nodes are defined by there single connection to the rest of the skeleton, these are seen as endpoints of the path.

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.7\linewidth]{files/e8e30db0dfadabbcf5bc6be64b02e066.png}
\caption[]{Leaf nodes identified on the skeleton graph. These nodes represent endpoints used during path generation.}
\label{fig-skeleton_leaves}
\end{figure}

Finally, starting from the closest leaf node to the robot, the full path is planned by recursively tracing the graph from the current leaf node to the nearest unvisited leaf node. Use the slider below to visualize the full path

\paragraph{Grid Based Spanning Tree Planner}

Secondly a grid based spanning tree algorithm is used to plan a full coverage path over the map. This planner is based on

\textbf{Input:} Occupancy grid $\mathcal{M}$, robot start position $\mathbf{p}_0 \in ℝ^2$, scale $s = 0.06$\newline
\textbf{Output:} Ordered waypoint segments $\mathcal{P} = [P_1, P_2, \ldots, P_k]$


\bigskip
\centerline{\rule{13cm}{0.4pt}}
\bigskip

\begin{enumerate}
\item $B \leftarrow$ threshold($\mathcal{M}$, lethal\_threshold)
\item $B_{down} \leftarrow$ resize($B$, scale $= s$, interpolation $=$ NEAREST)
\item $G \leftarrow$ gridGraph($B_{down}$) ~~~~\textit{(4-connected)}
\item Remove all edges $(u, v)$ where $B_{down}[u] = 0$ or $B_{down}[v] = 0$
\item $T \leftarrow ∅$
\item \textbf{For each} connected component $\mathcal{C} \in G$:

\begin{enumerate}
\item $T \leftarrow T ∪$ DFS\_tree($\mathcal{C}$)
\end{enumerate}


\item \textbf{For each} edge $(u, v) \in T$: ~~~~\textit{(edge subdivision)}

\begin{enumerate}
\item $m \leftarrow \frac{u + v}{2}$
\item replace $(u, v)$ with edges $(u, m)$ and $(m, v)$
\end{enumerate}


\item $P_{perim} \leftarrow \mathbf{0}^{H \times W}$, $\quad r \leftarrow \lfloor \frac{1}{4s} \rfloor$
\item \textbf{For each} node $p \in T$:

\begin{enumerate}
\item $p_{img} \leftarrow \frac{p + 0.5}{s}$
\item drawFilledRect($P_{perim}$, centre $= p_{img}$, halfsize $= r$)
\end{enumerate}


\item $\mathcal{C} \leftarrow$ findContours($P_{perim}$, RETR\_EXTERNAL)
\item \textbf{For each} contour $c \in \mathcal{C}$:

\begin{enumerate}
\item $W \leftarrow$ pixelToWorld($c$)
\item \textbf{If} $|W| < 2$: skip
\item $idx \leftarrow \arg\min_i \|W[i] - \mathbf{p}_0\|_2$
\item $P_i \leftarrow [W[idx], \ldots, W[ -1], W[0], \ldots, W[idx -1]]$
\item append $P_i$ to $\mathcal{P}$, set $\mathbf{p}_0 \leftarrow P_i[last]$
\end{enumerate}


\item sanitiseWaypoints($\mathcal{P}$, $\mathcal{M}$)
\item \textbf{Return} $\mathcal{P}$
\end{enumerate}


\bigskip
\centerline{\rule{13cm}{0.4pt}}
\bigskip

As opposed to the Skeleton planner, this planner makes use of the binary costmap directly. Using this binary costmap, it is further discretized to a grid which is the fraction of the resolution of the original costmap.
\texttt{Figure \{number\} \textless fig-spanning\_grid\textgreater }.

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.7\linewidth]{files/e52ef7a18be6de16816e8de02870820d.png}
\caption[]{Downsampled free-space grid used to construct the spanning tree graph.}
\label{fig-spanning_grid}
\end{figure}

A degree first search (DFS) is conducted over the free cells, from which sparse waypoints are created.

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.7\linewidth]{files/9bd57ec272547ef8da4e9ef4f69fa75f.png}
\caption[]{Depth-first search spanning tree generated over the free-space grid.}
\label{fig-spanning_dfs}
\end{figure}

A black image, of the same resolution as the original costmap is then created and white squares, with half the cell width, are placed in the center of each cell and in between each cell. Waypoints are created from the contours of this tree. These waypoints represent a circumnavigation around the DFS tree.

\centering

\caption[]{Coverage waypoints generated by tracing the contour around the spanning tree structure.}
\label{fig-spanning_waypoints}
\end{figure}

A segment from this circumnavigation is then removed from the path
