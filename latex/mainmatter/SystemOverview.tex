    \subsection{Mechanical}

    \subsubsection{Original MIRTE Master Platform}

    The project is based on the MIRTE Master V2. The platform consists of a mobile
    base propelled by 4 individually driven mecanum wheels and a robotic arm,
    allowing the robot to navigate through an environment and interact with
    objects.

    The original MIRTE Master hardware consists of three main parts:

    \begin{enumerate}
        \item \textbf{Mobile base}
        \item \textbf{Electronics}
        \item \textbf{Robotic arm}
    \end{enumerate}

    The mobile base utilizes four geared DC motors with Hall encoders, connected to
    97mm Mecanum wheels. This allows the robot to move in multiple directions
    without having to turn first, which is useful for navigating in small indoor
    spaces. The base also contains various sensors, such as rearward facing
    ultrasonic sensors, an IMU, a 2D LiDAR, a RGBD camera (depth camera) and a RGB
    camera mounted on the robotic arm.

    The electronics of the original platform are based on an Orange Pi 3B and a
    Raspberry Pi Pico H. The Orange Pi functions as the main computer, while the
    Pico is used for lower-level control tasks such as controlling the motors and
    general interfacing. The MIRTE Master also includes a custom-made PCB to
    connect the motors, sensors, and power system in a structured manner. The main
    powersource for the MIRTE Master is a 5Ah 12v Lion parkside drill battery.

    The robot arm is mounted on top of the mobile base. The manipulator has 4
    degrees of freedom, which are driven by 4 serial bus servo motors of varieing
    strength. A gripper and a RGB camera are mounted at the end of of the arm for
    object scanning and manipulation.

    \subsubsection{Design Goals for Our Modified Robot}

    The goal of our hardware modifications was to make the MIRTE Master more
    suitable for collecting and transporting small waste objects. This required
    changes to the chassis and and gripper design.

    The main design goals were:

    \begin{itemize}
        \item Increase the stiffness and reliability of the chassis.
        \item Add space for collecting and separating waste.
        \item Mount the camera in a useful position for object recognition.
        \item Improve the battery mounting system.
        \item Improve cable management.
        \item Modify the gripper so it can pick up waste objects more reliably.
    \end{itemize}

    \subsubsection{Chassis Modifications}

    The original MIRTE Master chassis was designed as a general-purpose mobile
    manipulator base. For our use case, the robot also needed to carry waste bins
    and support the manipulator during picking tasks. Therefore, the chassis was
    modified to improve strength and usability.

    The chassis consists of 6 side panels and a top and a bottom plate. In the
    original model, the top and bottom plates were made out of clear PMMA. While
    PMMA allows the user to see the status of the electronics clearly by looking at
    the LED's on the inside, it also has a tendency to shatter easily if bendt too
    much. In early testing of the MIRTE Master it has already shown that the PMMA
    was not a good choice for any type of loading resulting in shattered PMMA.
    Therefore we chose to change the material of all plates from PMMA to aluminium
    with a similair stiffnes, the difference of this being that aluminium can bend
    way more and will not shatter. To still be able to see the status of the
    electronics by the LED's we chose to print the 6 side panel elements out of a
    semi-transparent material.

    Two separate waste bins were added to the robot. These bins allow the robot to
    collect, store and seperate objects after picking them up.

    \subsubsection{Electronics Modifications}

    The original MIRTE Master already contains the main electronics needed for
    navigation and control. A RGB camera for object recognition was mounted
    overlooking the gripper. The camera needs to be placed in a position where it
    has a clear view of the area in front of the robot and the workspace of the
    gripper. This is important because the vision system must detect objects and
    classify objects effectively.

    The battery mounting system got a revision making the battery mounting more
    secure and userfriendly. A secure battery mount is important because the robot
    moves in different directions, and sudden movements can shift loose components.

    \subsubsection{Gripper Modifications}

    The gripper is an important part of the lab-cleanup robot because it directly
    interacts with the objects that need to be collected. The original MIRTE Master
    gripper is useful as a general robotic gripper, but the cleanup task requires
    it to handle different small objects reliably.

    The original gripper geometry is suited for holding small and larger objects
    however the gripping surface is not. Electronic trash tends to have small
    contact points for the gripper so good gripping performance is a must. For
    improving the grip on objects the contact patches are layered with a layer of
    soft 83A TPE coated with an additional layer of Bison Rubber anti-slip coating.

    \subsection{Navigation}

    The navigation stack of this robot is responsible for three main tasks:

    \begin{itemize}
        \item Mapping
        \item Coverage
        \item Object Approach
    \end{itemize}

    \subsubsection{Mapping}

    Before the robot can navigate properly through the environment and ensure
    proper coverage, this environment must first be known. Thats where mapping
    approaches come in handy. Several advanced and specialized mapping approaches
    exist already, but in this paper only one was considered. Frontier based
    mapping. Once the environment is mapped \{sufficiently\} the robot is allowed
    to navigate the space and propagate its behavior further down the tree.

    \subsubsection{Coverage Planning Algorithms}

    This section presents the coverage planning algorithms employed in this study.
    While a comprehensive technical analysis of these algorithms is beyond the
    scope of this work, \newline they are described with sufficient detail to
    enable understanding of their application within our framework. 
    
    \switchcolumn
    
    For in-depth technical details and formal derivations, the reader is referred to
    the original publications cited herein.

    In order to demonstrate the different navigators, \newline we use a map
    provided by the \href{https://github.com/MartijnWisse/mirte\_navigation}{mirte
        navigation} ros2 package. \newline

    \paragraph{The Free space Polygon}

    Each defined navigator must update its internal map and as a result plan a path
    over this map.

    A function first takes the costmap and, given a threshold, sets the free space
    to 0 and occupied space to 1. \newline It then detects the boundaries of the
    free space and saves these as contours.

    \paragraph{Boustrophedon Coverage}

    The first navigator that will be covered is a Boustropedon based Coverage
    planner. \newline This navigator plans in two steps:

    \begin{itemize}
        \item Decomposition
        \item Swath Generation
    \end{itemize}

    \subparagraph{Boustrophedon Cellular Decomposition}

    To effectively cover the entire map with boustrophedon (back and forth) swaths,
    the map is first partitioned (decomposed) into smalller areas that can be
    covered fully with these swaths. This is done by sweeping a straight line
    across the map and creating new cells where the connectivity of this line
    decreases. Cells are closed and a new one opens when this connectivity
    increases again or the line is fully restored, The results of Boustrophedon
    cellular Decomposition can be viewed in the cell below.

    \subparagraph{Boustrophedon Path Generation}

    After decomposition, each cell is populated with a boustrophedon path. Swaths
    are generated as straight lines parallel to the line used during decomposition.
    The transitions, often called headlands, are then generated to create one
    continuous path inside the cell.

    \includegraphics[width=0.7\linewidth]{figures/2d7b2cbc1b8dc1aa7aa5a49495009de2.png}

    \paragraph{SkeletonPath}

    The \texttt{SkeletonPath} planner is a topology-based coverage planner that
    generates navigation paths using the morphological skeleton of the environment.

    Unlike the \texttt{BousPath} planner, which decomposes the free space into
    sweepable cells, the skeleton planner reduces the free space to a graph-like
    centerline representation. This representation preserves the connectivity of
    the environment while simplifying path planning. The implementation is inspired
    by recent work in morphology-based exploration and autonomous navigation.

    \switchcolumn

    \subparagraph{Reading and Skeletonizing the Map}

    The skeleton planner generates a morphological skeleton. Internally, the
    planner fills the free-space contours, skeletonizes the free-space region,
    extracts skeleton pixels, and converts them into Cartesian waypoints. The
    generated waypoints are then stored.

    \subparagraph{Path Planning}

    After the waypoints have been generated, they are then sampled and ordered.
    \newline The algorithm does this by first constructing a graph representation
    of the skeleton tree. \newline The waypoints then become graph nodes. Edges are
    generated between the nodes with a certain distance threshold.

    To efficiently identify neighboring points, a k-d tree is used for spatial
    indexing. \newline Starting from the closest waypoint to the robot, the
    algorithm recursively explores nearby nodes and connects them within the graph.

    Leaf nodes are then identified in the tree, (nodes with one connection).

    \includegraphics[width=0.7\linewidth]{figures/4599d3c4df780082d726948f94d0cc2d.png}

    \subparagraph{Path Ordering}

    First the closest leaf node to the robot is found, this is the starting
    position. \newline The planner traces a path along the tree and selects the
    shortest one to the next leaf node. \newline It then appends these points to
    the path and sets this new leaf node as the current one and marks it as
    visited. \newline The algorithm repeats this process untill all leaf nodes have
    been explored successfully.

    \subsection{Perception}

    Perception is responsible for object detection, classification and spatial
    localization. For this study we limited the object detection and localization
    approaches to two. A \textbf{2D detection and depth projection} approach, and
    3D segmentation with \textbf{point cloud clustering}. As for classification
    methods, this study evaluates a classical cv approach, aswell as a
    classification model based approach.

    objects are categorized into:

    \begin{enumerate}
        \item Graspable vs non-graspable
